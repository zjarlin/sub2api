## 后端策略

- 健康证据以账号 ID 与模型 ID 为单位保存，映射别名和大小写变体合并判断冷却；一个模型的成功不代表同账号其他模型健康。
- 自动付费探测至少间隔 168 小时，原配置更长则保留。成功、失败和无结果的尝试都进入冷却；正常请求的已有健康证据也能避免额外探测。

## 请求预算

自动探测使用短提示 `Reply OK.`，不带历史消息或工具 schema；通用 Chat、Responses、Anthropic、Gemini 路径设最多 256 输出 token。这个数字是预算上限，模型回答短文本时按实际使用量计；没有强行设为 1，避免默认推理消耗预算后产生空输出。

API Key 路径去除不必要的合成系统提示和缓存写入配置。OAuth 保留供应商要求的身份信息和消息数组。VibeX、原生 Grok CLI 代理等有参数兼容限制的路径只使用支持的字段和短提示，仍受后台请求超时约束，不能声称这些端点具有相同 token 上限。Antigravity 周期健康探测也使用短提示和 256 token 上限，单次调用，不进入智能重试或额外积分消费流程；显式管理员诊断保留原流程。

自适应账号的周期健康探测只调用首选原生协议；管理员显式诊断仍可验证多个协议。无生成内容、错误或不完整流不能成为新的健康证据。最小文本探测不能证明工具、视觉、长上下文等能力均可用。

## 是否存在免费原生探活

本次查到的官方资料没有提供统一、免费且能证明“当前账号 + 指定模型真实推理可用”的标准。

| 操作 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 模型列表或单模型元数据 | 服务声明存在的模型和能力 | 当前账号额度及实际生成成功 |
| 引擎 `/health` | 服务或引擎健康 | 指定远端账号与模型能完成推理 |
| token 计数 | 输入长度及格式处理 | 生成链路可用 |
| 最小真实推理 | 该次请求执行成功 | 未来始终可用或所有能力正常 |

实际读取的官方资料：

- [vLLM `/health`](https://docs.vllm.ai/en/latest/api/vllm/entrypoints/serve/instrumentator/health/) 调用 `client.check_health()`；没有引擎的 render-only 服务也能返回 200，说明服务探活不能代替模型生成验证。
- [Anthropic 官方 SDK](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/src/anthropic/resources/messages/messages.py) 将 token 计数描述为不创建消息的操作（`without creating it`）；计数接口不能替代生成验证。
- [Google GenAI 官方 SDK](https://raw.githubusercontent.com/googleapis/python-genai/main/README.md) 分别提供模型列表、远程计数、本地 tokenizer 和生成操作。

不生成 token 不等于供应商承诺免费；可能仍有请求配额或自建算力成本。本机访问 OpenAI 官方文档返回 403，Anthropic 文档跳转地区不可用页，Google 定价页面超时，本次没有实时核实各供应商的免费计价承诺。最省额外额度的证据是复用正常业务请求的成功记录。
