# Responses 换号与模型降级的隐式压缩

客户端仍使用同一个会话。HTTP Responses 在换账号、跨透传模式或模型降级时，网关先整理可读历史，再向候选模型请求纯文本摘要，最后将摘要和当前任务交给该模型继续执行。

- 摘要使用普通 Responses 请求，不调用原生 `/responses/compact`，不把旧推理密文交给新模型。
- 摘要回合不提供工具，不携带客户端会话标识或旧 Codex 回合状态，结果不会写入客户端响应。
- 主请求保留 instructions、system/developer 约束、工具定义、最新用户请求、末尾工具结果及对应调用、图片等非文本输入。更早的工具执行记录进入摘要，要求区分已完成、失败、未知和尚未执行的操作。
- 同一 HTTP 请求的后续候选复用已经整理好的输入，模型切换不会重置降级标记或摘要。客户端 session 标识保持不变，旧 turn-state 和 turn-metadata 被清理。
- 单条用户请求、只有当前工具回合的输入，以及原生压缩请求不额外执行隐式摘要。摘要更长时使用清理后的原文。

摘要沿用已有压缩预算和辅助用量记账，每块最多 64 KiB；默认最多 32 块、总时限 120 秒。摘要与主请求共用所选账号的并发槽位，摘要失败也会释放槽位。可重试上游错误继续走原有换号和模型降级规则；无效摘要不会作为任务结果返回。

收到 `invalid_encrypted_content` 后，普通与透传 HTTP/JSON/SSE 路径在尚未输出正文或工具内容时共享一次恢复重试：移除失效推理项，保留可读压缩摘要和原有工具记录。已输出语义内容或清理后仍失败时不再重放。

网关签发的 `sub2api_compact_v1:` 历史在清理前解密还原。对于只有上游不透明压缩密文、没有可读摘要的输入，网关无法重建早期历史，不会以删除该项的方式伪造恢复成功。`previous_response_id`、服务端 conversation 和托管工具状态仍受现有降级可移植性检查约束；保留内容和目标模型能力仍需满足既有账号预检。

回归验证涵盖真实 handler 的连续模型降级、同模型换号、摘要失败后的降级、并发槽位释放、流式响应隔离、当前工具结果和用户约束保留，以及普通/透传的密文错误恢复边界。
