# 模型档位与自动降级

管理入口：系统设置 → 网关服务 → 模型档位与自动降级。

配置存放在 `settings.model_fallback_policy`，通过管理端 `GET/PUT /api/v1/admin/settings/model-fallback` 读写。推荐配置通过 `GET /api/v1/admin/settings/model-fallback/preset` 获取，载入后需要保存。未保存配置时使用内置推荐；关闭开关后仅保留同名账号重试。通用设置的保存不会覆盖此独立配置。

每档包含名称与精确模型 ID，档位数组由高到低排列。手动指定模型的同名账号重试耗尽后，先按该档的填写顺序尝试其他模型，再逐档往下；仍未成功时，从原请求最近的高档开始逐档向上补偿，包含最高档。补偿模型继续通过分组权限、请求能力和利润检查，费用按实际模型记录。等价 ID 在“全局模型同义词”中配置，档位使用规范 ID，执行时自动归一化去重；未评级的模型不猜测档位。一次请求固定候选清单，每个模型最多进入一次，配置最多 12 档、256 个模型。客户端取消和既有超时仍立即生效。

新增渠道后需要核对上游目录里的精确 ID。独立账号测试成功只说明该账号接受传入的 ID，不代表规范 ID 已经能匹配到它。例如 `deepseek/deepseek-v4.1-flash` 必须显式归入 `deepseek-v4.1-flash` 的同义词组；转发仍保留渠道要求的 `deepseek/` 前缀。版本、`fast`、`vision-exp` 等变体不会自动合并。

## auto 选模的成本边界

`auto` 排除已配置模型档位中的最高档（`tiers[0]`，即“夯”档），不在初选和失败降级时进入该档。未保存自定义分档时，内置最高档是 `AA 50+`，当前包含 `gpt-6-astra`。档位模型及其显式同义词按本次请求的设置快照排除，渠道、合成路由和账号的实际上游改名同样需要通过检查。Responses 转 Chat 的协议回退、compact 专用模型和重试也不能进入最高档。

Auto 的执行顺序独立于手动指定模型的逐档降级，采用「能力档位优先、档内性价比次序」两级排序：先按已配置能力档位从高到低（`ranks` 为档位号乘以 1000 加档内序号），同一档位内再按用户指定的性价比顺序——GLM 系列先于其他 DeepSeek、Kimi、MiniMax、Mimo、Qwen3、Step 系列，其余文本模型最后，未评级模型排在所有已评级模型之后。因此 `gpt-5.6-terra` 在手动档位降级中降到同档末尾，从 `deepseek-v4.1-flash` 降级时同档 GLM/Qwen 先于 Terra，通用档中 `glm-5.2` 与 `sensenova-6.8-flash-lite` 相邻进入降级路线；品牌加成只在同一档位内生效，不会让低档模型（如通用档的 `glm-5.2`）反超更高档的可用模型。`deepseek-v4.1-flash` 作为用户指定的首选无视档位固定排在最前，同一规范组内规范名先于带前缀的重复项。以模型 ID 保证稳定顺序。这是用户指定的性价比偏好，不是逐供应商实时报价；System One 不参与该确定性选择，决策账号离线不会阻断 Auto。

每次 Auto 请求从当前 Key 分组的完整账号清单读取模型映射与已同步上游目录，保留所有具体模型、别名和不同供应商来源，不再受健康成功记录或手工 256 模型分档上限限制。未知品牌的文本模型可以候选，实际协议由账号和显式合成路由决定。专用翻译、向量等模型、现有黑名单和最高档、离线或能力不匹配的来源保留在候选元数据中并注明排除原因。不会越过 Key 的分组权限，也不能枚举上游尚未同步且没有配置的未知 ID；通配规则本身不是具体模型。

同模型账号重试之后沿固定链路换来源、换模型，每个模型与平台组合仅进入一次。仅在请求仍可重放时继续，保留工具、上下文、模态、已输出内容与取消检查，不裁剪历史、不移除必要工具；全部候选失败时返回真实错误，不保证所有供应商不可用时任务仍能完成。现有无平台维度的 OpenAI 模型池熔断只适用于 OpenAI 来源，其他来源继续使用其账号故障处理，避免同名模型跨供应商误熔断。

会话卡片和完整候选计划见 [Auto 路由观测](auto-route-observations.md)。

`auto` 在标准模型列表、单模型查询及 Codex 清单中统一声明 `input_modalities: ["text", "image"]`；已有的旧版 Auto 条目也会更新这份声明。图片请求按实际账号的原生视觉能力或已启用且可用的视觉助手进行筛选，缺少兼容候选时返回错误。客户端同步模型时应采用当前目录的输入模态，不能让旧的仅文本缓存覆盖服务端新声明。

关闭自动降级开关后，最高档排除仍对 `auto` 生效。档位设置读取失败或没有可用分档时，`auto` 返回不可用；排除后没有候选时不回退到最高档。公开候选及渠道映射过滤后为空时，模型目录也不展示 `auto`。手动指定具体模型沿用原有权限和调度规则。

最终转发命中排除规则时，作为本地策略限制交回换号流程，不消耗换号预算，也不会把拦截本身记为账号或上游故障。候选耗尽返回 `503`；此前已发生的真实上游尝试仍保留在诊断记录中。

## 执行边界

- 覆盖 OpenAI 兼容账号池的 HTTP Responses、Chat Completions、Messages 入口及其 SSE 模式，沿用现有账号限流、并发、渠道限制、模型能力与利润检查；不跨 API Key 分组或绕开平台路由。专用图片、向量及有状态 WebSocket 不套用文本能力档位。
- 服务端会话引用、托管工具状态、不可移植的文件/音视频/加密推理内容和已输出实质内容不跨模型重放。客户端 function/custom 工具和只包含这些工具的 namespace 保留输入原文；custom 的 grammar 定义沿用既有协议转换。
- Responses 的空文本、推理、拒绝和工具参数增量不算实质输出，继续缓冲；此后收到可重试失败仍可换号、换模型。非空增量（包括空格）和无法确认语义的畸形增量保留已输出边界，避免重复生成。
- 目录预筛选和实际选号后均检查已知上下文、最大输出、推理强度及原生图片能力。上下文使用请求字节数加输出预算保守估算，不截断历史；上游未声明的能力不能当作已验证保证。上游仍可能拒绝未知的协议差异。
- 中间失败、模型变更和账号快照都保留在监控链。请求模型用于请求归属，实际模型用于转发与降级后的计费，响应保留真实模型；附加 `X-Sub2api-Requested-Model`、`X-Sub2api-Fallback-Model` 响应头（响应头尚未提交时）。
- 可重放失败才进入降级；请求格式、权限、计费和明确停止重试的错误仍终止。所有兼容候选耗尽后必须返回最终错误，不伪造成功。
- 上游容量降载（HTTP 5xx 或流内终态携带 `server_is_overloaded` / `slow_down` 或过载文案）是请求级瞬时故障：先在同一账号上有界重试，用尽后再按档位换模型。OAuth/SetupToken 透传账号与 API-key 账号走同一判定，不再把降载 503 直接透传给客户端；降载信号不触发账号临时封禁。

## 验证

### 目录、降级计划与周期探测

`catalog.json` 的模型数只表示供应商公开的 ID 数量，不表示逐一推理成功、函数工具可用或完整能力认证。Auto 在请求开始时从分组账号构建候选计划，按同义词归一，并保留不同平台来源；所以公开目录数量、规范模型数量和模型/平台候选数量可能不同。每项都有执行顺序或排除原因，未知能力和未评级模型不能描述成已验证。手动模型档位的 256 项上限不限制 Auto 的完整候选计划。

Auto 失败重试使用请求内固定列表和单调递增下标，不递归重新生成子链。`TestAutoModelHTTPTraverses331CandidatesAndTerminates` 覆盖 331 个候选、Responses/Chat Completions、流式/非流式、末位成功及全失败，验证完整遍历与有界终止；这是模拟上游回归，不是 331 个真实模型的可用性证明。

供应商模型目录每 6 小时检查，已同步目录的新鲜窗口为 12 小时。推理健康探测独立每 15 分钟扫描一次，每批最多 10 个账号/模型对、并发 3、单次超时 45 秒；默认每对 168 小时到期，可按账号配置 24–8760 小时。成功、失败和近期真实调用都只推迟同一模型，未测试模型优先，再按最早检查时间推进。模型列表接口缺失时也检查明确配置的映射目标，并去除重复模型。旧实现按账号计时，每周只测一个模型，无法覆盖大目录；现已改为按模型推进。

331 个符合条件的账号/模型对，在无积压且所有结果正常持久化时需要 34 批，约 8.5 小时完成首次轮询；多账号、停机、禁用探测或不可调度账号会增加或阻止覆盖，不能承诺每周一定完成全网探测。GPT 系列、Arena 会话和专用媒体模型沿用自动探测排除规则；手动测试不受该排除限制。普通连通性探测不证明工具、视觉、长上下文或所有协议能力，这些需单独验证。所有上游同时失败、超时取消或请求无法重放时，Auto 返回真实错误。

回归测试覆盖同名账号先行、同档优先、低档耗尽后逐档向上补偿、跨多档成功、全部耗尽、禁用策略、未知模型、重复配置、状态引用、能力不兼容、取消及持久化读写。流式验证空增量后 502 继续补偿与真实输出后停止重放。前端验证配置载入、编辑排序、校验、保存及模型链展示。

## 运维终态分类

运维监控的“降级成功”统计账号重试、切换账号或切换模型后最终成功的请求，是成功请求的子集。概览字段为 `recovered_success_count`，明细使用 `GET /api/v1/admin/ops/upstream-errors?view=recovered`；计数与列表共用筛选条件。

新记录使用 `recovered_upstream` 类型，保留客户端请求模型、实际模型、最终成功账号和中间尝试。列表调用链直接完整展示（无需点击展开），详情中间失败为琥珀色、最终成功为绿色。默认请求错误和上游错误列表只显示最终失败，完整遥测可在“全部”视图查询。

HTTP 200 不等于请求成功：SSE `response.failed` 或请求级流内错误仍属于最终失败。历史 `Recovered ...` 记录只有在存在请求 ID、且没有同请求最终失败记录时才纳入成功；无法可靠关联的历史记录不补猜终态。格式、鉴权等不能重放的请求错误仍直接展示，不强行进入模型降级。

## 当前调度与目标算法的差距

### 已实现的调度流程

- 候选索引按“分组 × 目标平台 × 入站协议 × 规范模型 ID × 当前目录指纹”缓存账号 ID，TTL 为 2 分钟，最多 256 项。同义词、账号映射和上游目录变更会改变指纹。每次请求重新检查权限、健康、配额、并发、模型能力和利润，索引不缓存这些判断；没有可用候选时回到完整快照，保留原始诊断。
- 高级调度中，没有可用会话绑定的请求按实时综合分从高到低遍历全部候选，不再只尝试 Top-K。自动生成的会话哈希、已排除或已失效的旧绑定不会限制候选数量。加权会话绑定影响 Top-K 前，仅校验该绑定账号的最新状态；目录快照与数据库不一致时解除本轮绑定，继续全池排序，取消请求不删除持久绑定。现有会话健康逃逸将原账号放到最后兜底，保留原绑定；首名在数据库终检失效时继续尝试下一名。
- 可重放的普通连接错误、408 和 5xx 会先穷尽同一规范模型下的兼容账号，再按配置进入同档、低档和高档补偿模型，`MaxAccountSwitches=0` 也不会提前截断。请求错误、鉴权错误、取消、已输出实质内容及请求级瞬时降载沿用各自边界。
- 模型池熔断按“分组 × 入站协议 × 渠道映射后的规范选号模型”隔离，不使用客户端公开名或账号上游改名作为池键。60 秒内两轮完整池发生同类故障后冷却 60 秒；冷却后授予一个半开探针，租约 30 秒，每 10 秒按所有者续租。成功清除状态，失败重新冷却，取消或无结论释放探针。
- 模型池许可通过现有 `TempUnschedCache` 接入 Redis，原子协调多实例检查、计数、认领、续租和释放。Redis 出错会记录告警并放行，不将跨实例状态写入本地替代池；没有 Redis 存储时使用有容量上限的进程内状态。
- 池失败证据必须包含首次完整候选的账号 ID 集合，至少两个不同账号，且每个账号均有实际同类上游故障。会话命中、订阅优先子池、compact、旧调度未知候选数、加权绑定的目录与数据库漂移，以及因能力、利润或并发而跳过的候选均不能被推断为完整池失败。

全候选分数排序和完整池候选证据依赖 `openai_advanced_scheduler_enabled`；关闭高级调度时保留原选号策略，候选数未知的失败轮不会写入模型池熔断。已有服务端会话、响应引用、guardian 绑定及显式订阅优先策略仍保留原有约束。

### 剩余差距与边界

- 索引缓存的是候选账号 ID，不是固定分数排序。目录指纹仍扫描当前分组快照，复杂度为 O(N)；负载和综合分按请求重新计算。模型成功率与首字延迟仍在进程内，多实例评分尚未统一。
- 成本因子目前只能使用有来源的账号计费倍率，未接入所有兼容供应商的逐模型真实结算成本。现有账号探针仅提供倍率，账号统计中的价格未证明是上游成本；没有可信数据的候选保持中性，成本权重为零时不生效。
- 手动指定模型的档位降级顺序取自管理员配置，未评级模型不会自动猜测下一档。Auto 使用上述完整候选和性价比顺序；未知协议能力不能视为已验证兼容。有状态 WebSocket、专用图片和向量请求仍不参与文本档位降级。
- 半开探针依赖 Redis 租约和续租。持续网络分区或进程暂停超过租约时，其他实例可能接管；现有转发接口不能在失去租约后强制终止旧在途请求，因此不能声称在这些故障下仍保证实际请求绝不重叠。

本地回归覆盖实际 HTTP 两轮完整失败触发冷却、三种入站协议、SSE 失败、渠道映射变更隔离、失效会话继续选号和取消边界。Redis 测试覆盖两个真实缓存客户端及两个网关实例共用许可、唯一探针、长请求续租、所有者保护和断连放行。测试与 `-race` 只验证本地源码和进程内 HTTP 链路，不代表生产已部署或真实供应商请求已验证。
